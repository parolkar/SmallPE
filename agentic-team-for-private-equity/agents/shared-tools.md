# Shared Tools & Conventions

All SmallPE agents have access to the following tools and must follow these conventions.

## Available Tools

### 1. excel2md (`tools/excel_to_markdown/excel2md`)
Converts Excel files (.xlsx, .xls) to clean Markdown format. Preserves all sheets, tables, and data formatting.

**Usage:**
```
./tools/excel_to_markdown/excel2md convert input.xlsx -o output.md
```

### 2. pdf2md (`tools/pdf_to_markdown/pdf2md`)
Converts PDF documents to structured Markdown. Extracts metadata, tables, and preserves document structure.

**Usage:**
```
./tools/pdf_to_markdown/pdf2md convert document.pdf -o output.md
```

### Tool Usage Rules
- ALWAYS check if existing tools can handle your data format before creating new scripts
- Use these tools to convert documents to Markdown for easier analysis
- Store processed data in the relevant deal or analysis folder
- Only create new scripts if existing tools don't meet your needs
- Always add documentation at the beginning of any new scripts

## PDF Generation (Markdown to PDF)

SmallPE has a standardised PDF pipeline using pandoc + xelatex with branded templates.

**Standard command (one-liner):**
```
cd agentic-team-for-private-equity
sed 's/-->/-->/g' path/to/report.md | pandoc --defaults=templates/pandoc-defaults.yml -o path/to/report.pdf
```

**Template files (do not modify per-deal):**
- `templates/pandoc-defaults.yml` -- pandoc settings: fonts (Charter body, Inter headings, Fira Code mono), geometry, TOC, xelatex engine
- `templates/smallpe-report.latex` -- LaTeX header: SmallPE colors, fancyhdr (header/footer), titlesec styling, last-page attribution footer

**Override header text per-report** (e.g., for due diligence vs. IC report):
```
sed 's/-->/-->/g' report.md | pandoc --defaults=templates/pandoc-defaults.yml \
  -V header-includes='\fancyhead[L]{\textcolor{smallpegray}{\small\sffamily Due Diligence Report}}' \
  -o report.pdf
```

**The `sed` preprocessing step is mandatory** -- Charter font lacks unicode arrows. Always pipe through `sed 's/-->/-->/g'` before pandoc.

The last page of every PDF automatically includes: "Generated by SmallPE Agents -- www.smallpe.com / Sponsored by inloop.studio"

## Markdown Authoring Rules for PDF Compatibility

All agents writing markdown that will become a PDF must follow these rules:
1. **No unicode arrows** -- use `-->` instead of special arrow characters in text and tables
2. **No ASCII box-drawing or wide diagrams** -- use markdown tables or bullet-list hierarchies instead; A4/Letter columns are ~6.5in wide
3. **No emoji** -- Charter font does not render them; describe instead
4. **Table column count** -- keep tables to 6 columns max; wider tables overflow on print
5. **Code blocks** -- keep lines under 80 characters to avoid clipping
6. **Avoid raw HTML** -- pandoc's LaTeX engine ignores it; use markdown equivalents

When generating documents, always include the SmallPE branding in the footer with link to https://www.smallpe.com when creating or converting documents for external distribution.

## Developing Presentations

When creating presentations (decks, ppt, slide decks, pitch deck etc):

1. **Always use the Slidev tool** available in the SmallPE-presentations folder
2. **Contain all operations** within the SmallPE-presentations folder
3. **Start with inspiration**: Read the existing slides.md file first: `cd SmallPE-presentations && cat slides.md`
4. **Create topic-specific presentations**: Develop slides-TOPIC_NAME.md files
5. **Export format clarification**: After generating the markdown file, ask the user which export format they prefer:
   - **PDF Export**: `slidev export slides-TOPIC_NAME.md --format=pdf`
   - **PPTX Export**: `slidev export slides-TOPIC_NAME.md --format=pptx`
6. **Troubleshooting**: If Slidev commands fail, run `npm install` in the SmallPE-presentations folder first

Always ensure presentations maintain SmallPE branding and include https://smallpe.com in the footer or final slide.

## Efficiency Rule

For maximum efficiency, whenever you need to perform multiple independent operations, invoke all relevant tools simultaneously rather than sequentially.
